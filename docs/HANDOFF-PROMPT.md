## Что осталось — по приоритету

1. **Починить перф-панель `?perf=1` на телефоне: её перекрывает строка поиска.**
   Панель стоит `fixed inset-x-2 bottom-2 z-[60]`, поиск — сверху, но на телефоне
   панель уходит под нижние плашки. Владелец это видел. Проверить на 390×844 и
   поправить позицию/слой, затем показать скриншот.
2. **D1 — одна панель вместо колонки чипов.** Свёрнутая кнопка → категории,
   открыта максимум одна. Внедрять настоящий морф геометрии, а не `scale` картинки.
   Требует «да» владельца по языку (см. ниже).
3. **D2 — единые иконки POI.** Варианты приносить скриншотами, выбор за владельцем.
   «Жидкое стекло» запрещено. Набор путей уже есть: `web/app/icons.ts`.
4. **D5 — айдентика:** знак 16/512 px, заставка вместо наследия старого проекта,
   `og.jpg`, иконки манифеста. Плюс техдолг: файлы в `design/` — JPEG с расширением `.png`.
5. **S14 — бюджет производительности.** Приёмка: Lighthouse mobile ≥85,
   LCP < 2,5 с на 4G, JS < 300 КБ gzip, карта > 30 fps. **Известно:**
   JS **538 КБ gzip** (главный вклад — MapLibre, 357 КБ) → по весу не проходим.
   Локально с троттлингом CPU ×4: LCP 488 мс, fps 7,1, худший кадр 583 мс.
   Нужны числа с телефона владельца через `?perf=1`. Потом решить: резать движок
   или честно пересогласовать бюджет (300 КБ для карты с PMTiles — вопрос спорный).
6. **S11** — замер смысла №2: нужны 5 живых людей (владелец).
   **S13** — первый экран, только после S5. **S5** — замер смысла, протокол готов
   (`docs/S5-PROTOCOL.md`), перенесён владельцем в техдолг до редизайна.
   **S12** вырезана. **S15** (аналитика) — риск, не проверена.

## Правила работы (нарушать нельзя)

1. **Делегируй всё, что делается дольше пяти минут.** Один агент = один блок с
   проверяемой приёмкой. Формулируй бриф так, чтобы он был самодостаточен: агент
   не видит наш диалог.
2. **В брифе агента всегда указывай:** путь репозитория, ветку, запрет трогать
   `docs/`, требование прогнать `npx tsc --noEmit` + `npm run build` +
   `npm run e2e`, формат отчёта (≤10 строк, с числами), запрет пушить.
3. **Не верь отчётам агентов.** Проверяй сам: типы, сборка, тесты, а по UI —
   числами из DOM и скриншотом. Дважды в прошлой сессии агентский отчёт расходился
   с реальностью.
4. **Не раздувай контекст.** Не читай большие файлы целиком, не вставляй в ответ
   длинные логи, не дублируй то, что уже записано в `docs/`. Держи ответ владельцу
   коротким: что сделано, числа, что от него нужно.
5. **Экономь токены:** один прогон тестов — один вывод; скриншоты — по одному на
   вопрос; документацию обновляй точечными правками, а не переписыванием файлов.
6. **Только ветка + PR.** Прямой пуш в `main` запрещён (было нарушено один раз,
   записано в `DECISIONS`). После мержа проверяй, что `docs/` реально попали в
   `main`, и только потом удаляй ветку.
7. **Документация в конце каждого блока:** `docs/CONTEXT.md` (состояние + числа) и
   `docs/DECISIONS.md` (решение и почему). Это требование владельца.
8. **Не подгоняй тесты под код.** Если тест падает — сначала `test-results/**/error-context.md`,
   потом правка. Флак считается вылеченным при 10 зелёных прогонах подряд, не при двух.
9. **Приёмка должна быть числом.** «Стало красивее» не принимается: MAD, контраст,
   метры, миллисекунды, количество. Если число не сходится — работа возвращается.
10. **Новые фичи не пишутся в `web/app/map/engine.ts` и не растят `map.tsx`.**
    Логика — в модулях (`nearby-store.ts` — образец: кэши и загрузка внутри).

## Ловушки среды (проверено на себе)

- **`Invoke-WebRequest` в этой среде висит** («неинтерактивный режим»). Для HTTP —
  только `curl.exe` (`curl.exe -sI https://...`).
- **Телефон владельца ходит через Tailscale `100.66.193.24`**, а не через LAN
  `192.168.1.71`. Ссылки для него — на Tailscale-адрес. Локальный показ проб:
  `cd web && node probe2/serve.mjs "<abs path to web>"` → `/gallery`, `/probe2/`, `/probe3/`.
- **`gh` CLI не установлен.** Логи Actions недоступны. Мерж делает Autopilot по
  пушу ветки. После мержа деплой сам не запускается — нужен
  `gh workflow run deploy.yml --ref main -f data_ref=data` (но `gh` нет, поэтому
  проверяй `last-modified` у сайта: деплой приезжает за 5–15 мин).
- **CDN кэширует 10 минут.** Свежесть сайта проверяй по заголовку `Last-Modified`,
  а не по содержимому.
- **Никакого Python для анализа картинок/палитр** и вообще в брифах агентов:
  на кириллическом пути он ломает вывод, а один агент из-за этого молча умер.
  Анализ — на Node.
- **Файлы пиши инструментами записи.** Перезапись через PowerShell убивает
  кириллицу в комментариях (случалось дважды).
- **`web/probe2/bg.png` и `web/probe3/bg.png` намеренно не в git** (`.gitignore`).
  Пробы нельзя выложить на прод без force-add — показывай через локальный сервер.
- **e2e запускать только `npm run e2e`** (он поднимает сервер), не голым
  `npx playwright test` — иначе `ERR_CONNECTION_REFUSED`.
- **`web/public/data/` — untracked** (большие данные, приходят из Release). Не коммить.
- **`live/meta.json` в репозитории датирован 27.11**, поэтому тесты, зависящие от
  свежести, обязаны мокать мету через `e2e/live-meta.ts` (`mockFreshMeta` и др.).
