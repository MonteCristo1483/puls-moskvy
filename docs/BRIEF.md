# BRIEF — общий контекст для команды (читать первым)

Новый продукт на базе готового движка. Репозиторий: `puls-moskvy` (приватный). Название — **Пульс Москвы**.

## Видение владельца (дословно, не переформулировать в сторону)

«Интерактивная Москва — слепок города: что происходит сейчас, что было и что будет. Ветер, погода, заведения, стройки, события, ситуация на дорогах. Открываешь и изучаешь город: что тебя ждёт сегодня в 8 утра, откуда дует, куда летит пыль, что закрыто, где стройка».

Ядро продукта — **ситуация в городе**, а не «выбор квартиры». Адресная карточка дома остаётся как один из слоёв, но не как центр продукта.

## Что уже есть в репозитории (движок, не переписывать без задачи)

- `web/` — Next.js + TypeScript + MapLibre GL, 3D-здания, PMTiles, PWA, service worker.
- `pipeline/` — Python: OSM → PostGIS → скоринг → экспорт → tippecanoe → PMTiles.
- `config/scoring.json` — формула индекса (7 факторов: транспорт, промзоны, доступность, зелень, дом, плотность, ветер).
- Данные: 153 280 жилых домов с баллом, 132 района, красные зоны, 14 980 POI, 646 тыс. деревьев. Данные лежат в GitHub Release, в репозиторий не коммитятся.
- Сборка/деплой: GitHub Actions (`Deploy`), GitHub Pages, `data.zip` из Release.
- **Бэкенда нет.** Всё статическое.

## Ограничения (жёсткие)

1. Один владелец, не программист. Работа идёт агентами; каждая задача — отдельная сессия с брифом.
2. Бюджет на ИИ ограничен (десятки сессий, не сотни). Всё, что можно сделать без нового пайплайна, делается без него.
3. Данные — только открытые и легальные: OSM (ODbL, атрибуция), data.mos.ru (CC BY 4.0), Open-Meteo/ERA5. Платные/закрытые API (Яндекс.Пробки) — только если владелец отдельно решит.
4. Никаких выдуманных измерений: не публикуем концентрации и децибелы, если нет замеров. Только факты, расстояния, оценки с оговоркой.
5. Пока — GitHub Pages. Бэкенд/хостинг меняются только с обоснованием и ценой.
6. Язык продукта — русский, интерфейс — mobile-first.

## Правила для этой команды

- Ты пишешь **только свой документ**. Код не трогаешь. Чужие документы не правишь.
- Каждый документ ≤120 строк, без воды, с конкретикой: числа, шаги, метрики, критерии приёмки.
- Всё, что не проверено, помечай `[не проверено]`. Всё, что требует денег/времени, — с оценкой.
- Не пересказывай этот бриф. Пиши то, чего в нём нет: решения, приоритеты, цифры.

## Твои файлы по роли

- **Product** → `docs/PRODUCT.md`: позиционирование, персона, сценарий-ядро, что входит в MVP, что не входит, метрики успеха, гипотеза монетизации.
- **Delivery** → `docs/ROADMAP.md`: 3 вехи, задачи по 1 сессии, критерии приёмки, порядок, риски, что режем.
- **CTO** → `docs/ARCHITECTURE.md`: какие потоки данных реально доступны (свежесть, лицензия, стоимость), нужен ли бэкенд и какой, хостинг, обновление данных, риски и их цена.
